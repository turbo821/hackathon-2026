# Invoice Keeper — напоминания о регулярных платежах

Система, которая не даёт забыть о регулярных платежах: аренда, подписки, серверы.
Администратор вносит платежи. За 3 дня до срока система напоминает о них в
Telegram-чат и по почте. Пользователи отмечают оплату и следят за просрочками.

Система отвечает на три вопроса: **что и когда оплатить, что уже оплачено и что просрочено.**

## Быстрый старт (Docker)

Нужны Docker и Docker Compose. База отдельно не нужна, это SQLite.

```bash
# 1. Настройки: копируем шаблон
cp .env.example .env

# 2. В .env обязательно:
#    JWT_SECRET_KEY — случайная строка (openssl rand -hex 32)
#    SUPERADMIN_*   — логин, пароль и email администратора
#    TELEGRAM_*     — для напоминаний (см. «Настройка Telegram»)

# 3. Запуск
docker compose up --build
```

> Пишите `--build` после каждого `git pull`. Иначе Docker возьмёт старый образ.

Поднимаются три сервиса:

| Сервис | Что делает | Адрес |
|--------|-----------|-------|
| `backend` | API (FastAPI). При старте применяет миграции, сверяет схему БД и создаёт администратора и демо-данные | http://localhost:5000 |
| `frontend` | Веб-панель (Vite) | http://localhost:5173 |
| `worker` | Фоновые напоминания по расписанию и Telegram-бот (кнопка «Оплачено», привязка аккаунтов) | — |

Полезные адреса:

| Что | Адрес |
|-----|-------|
| Панель | http://localhost:5173 |
| Swagger | http://localhost:5000/api/v1/docs |
| ReDoc | http://localhost:5000/api/v1/redoc |
| OpenAPI (живая) | http://localhost:5000/api/v1/openapi.json |
| OpenAPI (файл) | [`backend/openapi.json`](backend/openapi.json) |
| Проверка живости | http://localhost:5000/api/v1/health |

Остановка: `docker compose down`. Данные при этом сохраняются (см. [Хранение данных](#хранение-данных-миграции-сброс-базы)).

Без настроенного Telegram приложение работает полностью. Напоминания просто не
отправляются, и worker пишет об этом в лог.

## Тестовые учётные записи и данные

Вход в панель — **по email и паролю**.

| Роль | Email | Пароль | Откуда |
|------|-------|--------|--------|
| Суперадмин (owner) | `SUPERADMIN_EMAIL` из `.env` (в шаблоне `superadmin@example.com`) | `SUPERADMIN_PASSWORD` (в шаблоне `superadmin`) | `.env` |
| Администратор | `manager@example.com` | `manager12345` | демо-данные |
| Пользователь | `user@example.com` | `user12345` | демо-данные |
| Пользователь | `anna@example.com` | `anna12345` | демо-данные |

Демо-платежи по требованию кейса (все ежемесячные, срок — день первого запуска):

| Платёж | Сумма | Валюта |
|--------|-------|--------|
| Аренда офиса | 85 000.00 | RUB |
| VPS-сервер (Hetzner) | 49.90 | USD |

Демо-данные создаются один раз, повторный запуск дублей не создаёт. Чтобы их
отключить, задайте `SEED_DEMO_DATA=false`.

## Сценарий демонстрации

Полный путь из кейса: от добавления платежа до следующего периода.

**Основной сценарий**

1. **Войти администратором.** Откройте http://localhost:5173 и войдите как `manager@example.com` / `manager12345` или как суперадмин из `.env`.
2. **Добавить регулярный платёж.** Вкладка «Регулярные» → «+ Добавить платеж». Укажите название, сумму, валюту, периодичность и дату ближайшей оплаты. Возьмите дату не дальше чем через 3 дня, чтобы напоминание пришло сразу.
3. **Получить напоминание в Telegram.** Сообщение придёт в чат из `TELEGRAM_CHAT_ID` сразу после создания платежа. В нём будут название, сумма, валюта, дата и кнопка «✅ Оплачено».
4. **Войти пользователем и отметить оплату.** Выйдите и войдите как `user@example.com` / `user12345`. На вкладке «Платежи» нажмите «Оплатить» у нужного периода. Отметить оплату можно и кнопкой «Оплачено» в Telegram, если аккаунт привязан (см. [Настройка Telegram](#настройка-telegram)).

**Просрочка и периоды**

5. **Показать просроченный платёж.** Создайте платёж с датой в прошлом, например неделю назад. Он сразу появится со статусом «Просрочка N дн.», а сумма попадёт в «из них просрочено» на карточке валюты. Фильтр «Просрочено» покажет только такие платежи.
6. **Исправить фактическую дату оплаты.** Отметьте просроченный период оплаченным: статус станет «оплачено · опоздание N дн.». В колонке «Действие» поменяйте дату в календаре на день срока. Опоздание исчезнет, а срок останется прежним.
7. **Показать следующий период с отдельным статусом.** Как только текущий период оплачен, в списке появляется следующий (через месяц, квартал или год) со своим статусом «Не оплачено». Прошлый период остаётся в истории.

## Роли и права

В кейсе две роли: администратор и пользователь. В решении администратор из
`.env` — это **суперадмин** (в интерфейсе подписан как *owner*). Он может всё,
что требуется от администратора по кейсу. Дополнительно он может назначать
обычных администраторов, чтобы не раздавать всем один пароль из `.env`.

| Действие | Суперадмин (owner) | Администратор | Пользователь |
|----------|:---:|:---:|:---:|
| Смотреть платежи, периоды и итоги | ✅ | ✅ | ✅ |
| Отмечать и отменять оплату, исправлять фактическую дату | ✅ | ✅ | ✅ |
| Добавлять и прекращать регулярные платежи | ✅ | ✅ | ❌ |
| Создавать, менять и удалять обычных пользователей | ✅ | ✅ | ❌ |
| Журнал оплат (`GET /payments`) | ✅ | ✅ | ❌ |
| Создавать и менять администраторов, менять роли | ✅ | ❌ | ❌ |

- Суперадмин задаётся **только в `.env`** (`SUPERADMIN_USERNAME`, `SUPERADMIN_PASSWORD`, `SUPERADMIN_EMAIL`). Через панель и API его нельзя изменить, удалить или создать второго. При каждом старте контейнера сид `scripts.seed_superadmin` приводит аккаунт к значениям из `.env`.
- Логин и email суперадмина зарезервированы: занять их другим пользователем нельзя.
- Ограничения действуют в API, а не только в интерфейсе. Скрытые кнопки в панели — лишь удобство.
- После удаления пользователя его токен перестаёт работать. В истории оплат вместо него остаётся пустая ссылка.

## Правила учёта: периоды, статусы, просрочка

**Регулярный платёж** — это шаблон: название, сумма, валюта, дата ближайшей
оплаты и периодичность (ежемесячно; дополнительно ежеквартально и ежегодно).

**Период** — конкретная оплата шаблона со своей датой и отметкой «Оплачено / Не оплачено».

- Периоды создаются от первой даты с шагом периодичности, вплоть до ближайшего неоплаченного периода со сроком сегодня или позже. Если первая дата в прошлом, создаётся вся история.
- Оплатили текущий период — сразу появляется следующий.
- Просрочка не останавливает следующие периоды: когда наступает новый срок, появляется новый период.
- Если такого числа в месяце нет, срок переносится на последний день месяца. Даты считаются от исходного числа, без «уползания»: 31.01 → 28.02 → 31.03.
- Все даты («сегодня», просрочка, окно напоминаний) считаются в едином часовом поясе `APP_TIMEZONE`, а не в поясе сервера.

**Статусы периода**

| Состояние | Когда |
|-----------|-------|
| Ждёт оплаты (`pending`) | Не оплачено, срок сегодня или позже |
| Просрочено (`overdue`) | Не оплачено, со **следующего дня** после срока |
| Оплачено (`paid`) | Оплачено в день срока или раньше. Оплата в день срока — вовремя |
| Оплачено с опозданием (`paid_late`) | Оплачено после срока |

- При отметке «Оплачено» указывается фактическая дата. Без даты ставится сегодня. Будущую дату указать нельзя.
- При отмене отметки дата оплаты очищается.
- Просрочка не хранится в базе, а считается при чтении. Поэтому исправление фактической даты сразу убирает ошибочную просрочку, а срок не меняется.

**Прекращение платежа** (`DELETE /recurring-payments/{id}`): платёж становится
неактивным, новые периоды и напоминания больше не создаются. Будущие
неоплаченные периоды удаляются. Оплаченные и уже наступившие периоды остаются
в истории с пометкой «платёж прекращён».

## Напоминания

Как это работает:

1. Worker раз в `REMINDER_CHECK_INTERVAL_SECONDS` (по умолчанию 60 с) досоздаёт недостающие периоды и проверяет сроки.
2. Он выбирает **неоплаченные** периоды **действующих** платежей со сроком в окне *от сегодня до сегодня + `REMINDER_DAYS_BEFORE`* (по умолчанию 3 дня), по которым ещё не напоминали.
3. Отправляет сообщение: название, сумма, валюта, дата оплаты и сколько осталось дней.

Правила:

- **Без дублей.** Перед отправкой период «захватывается» атомарным `UPDATE … WHERE reminder_sent_at IS NULL`. Повторная проверка или параллельный процесс второй раз его не отправят.
- **Платёж добавлен позже чем за 3 дня до срока** — напоминание уходит сразу при создании, не дожидаясь worker.
- **Оплаченный период** напоминания не вызывает.
- **Прекращённый платёж** напоминаний не создаёт.
- **Сбой отправки.** Если все каналы упали, отметка снимается, и на следующей проверке будет новая попытка.

Каналы:

| Канал | Куда | Условие |
|-------|------|---------|
| Telegram | Чат `TELEGRAM_CHAT_ID`, с кнопкой «✅ Оплачено» | Заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` |
| Email (SMTP) | Всем пользователям с email, одним письмом со скрытыми получателями. Адреса `@example.com` (демо) пропускаются | Заданы `SMTP_ADDR` и `SMTP_PASSWORD` |

## Настройка Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.
2. Добавьте бота в групповой чат, куда должны приходить напоминания.
3. Узнайте `chat_id` чата. Напишите в группе `@имя_бота тест`: из-за privacy mode бот видит только сообщения, где его упомянули. Затем откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьмите поле `chat.id`. У группы он отрицательный.
4. Пропишите в `.env`:

   ```env
   TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
   TELEGRAM_CHAT_ID=-1001234567890
   TELEGRAM_BOT_USERNAME=имя_бота
   ```

5. Перезапустите: `docker compose up -d --build`.

Если Telegram настроен, `GET /api/v1/health` вернёт `"telegram_configured": true`.

**Кнопка «Оплачено» в сообщении.** Чтобы бот понимал, кто нажал кнопку,
Telegram-аккаунт нужно привязать к пользователю системы. Есть три способа:

| Способ | Как |
|--------|-----|
| Ссылка на бота | `POST /api/v1/auth/telegram-link` возвращает одноразовую ссылку `t.me/<бот>?start=<код>`. Откройте её и нажмите «Start». Код живёт 15 минут и работает один раз |
| Ссылка-приглашение в чат | `POST /api/v1/auth/telegram-chat-link` возвращает персональную ссылку-приглашение. Бот привяжет аккаунт, когда человек вступит в чат. Нужен `TELEGRAM_GROUP_CHAT_ID`, а бот должен быть администратором чата с правом приглашать участников |
| Вручную | Напишите боту любое сообщение, он ответит вашим Telegram ID. Передайте его в `PATCH /api/v1/auth/me` (`{"telegram_id": 123}`) |

В журнале оплат будет имя пользователя из системы и источник `telegram`.
Кнопку и привязку обслуживает сервис `worker`, поэтому он должен быть запущен.

## Настройка почты (SMTP)

Почтовые напоминания — дополнительный канал. Пока `SMTP_PASSWORD` пустой,
письма не отправляются.

```env
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465                 # используется SMTP_SSL, порт 587 не подойдёт
SMTP_ADDR=you@mail.ru         # адрес ящика, он же логин
SMTP_PASSWORD=пароль-приложения
SMTP_NAME=Invoice Keeper
SMTP_SUBJECT=Напоминание об оплате
```

`SMTP_ADDR` не оставляйте пустым: пустое значение не проходит проверку формата email.

Проверить настройки (подключение, вход и список получателей):

```bash
docker compose exec backend python -m scripts.check_smtp
docker compose exec backend python -m scripts.check_smtp --to me@example.org   # + тестовое письмо
```

## API

Все эндпоинты — под префиксом `/api/v1`. Авторизация — заголовок
`Authorization: Bearer <token>`. В Swagger нажмите **Authorize**: сначала
выполните `POST /api/v1/auth/login`, затем вставьте `access_token`.

**Обязательные эндпоинты кейса**

| Метод | Эндпоинт | Назначение | Доступ |
|-------|----------|-----------|--------|
| POST | `/api/v1/auth/login` | Вход (email + пароль) | все |
| GET | `/api/v1/auth/me` | Текущий пользователь | авторизованные |
| POST | `/api/v1/auth/logout` | Завершение сессии (токен отзывается) | авторизованные |
| GET | `/api/v1/recurring-payments` | Список регулярных платежей (`include_inactive=true` — с прекращёнными) | авторизованные |
| POST | `/api/v1/recurring-payments` | Создание регулярного платежа | админ |
| DELETE | `/api/v1/recurring-payments/{id}` | Прекращение платежа и его напоминаний с сохранением истории | админ |
| GET | `/api/v1/payment-occurrences` | Периоды: оплаченные, просроченные, ожидающие | авторизованные |
| GET | `/api/v1/payment-occurrences/{id}` | Конкретный период | авторизованные |
| PATCH | `/api/v1/payment-occurrences/{id}` | Подтверждение или отмена оплаты, исправление даты | авторизованные |
| GET | `/api/v1/payments/summary` | Итоги по валютам | авторизованные |
| GET | `/api/v1/users` | Список пользователей | админ |
| POST | `/api/v1/users` | Создание пользователя | админ |
| PATCH | `/api/v1/users/{id}` | Изменение пользователя | админ |
| DELETE | `/api/v1/users/{id}` | Удаление пользователя | админ |
| GET | `/api/v1/docs` | Swagger-документация | все |

**Дополнительные эндпоинты**

| Метод | Эндпоинт | Назначение |
|-------|----------|-----------|
| PATCH | `/api/v1/auth/me` | Привязать или отвязать свой Telegram ID |
| POST | `/api/v1/auth/telegram-link` | Одноразовая ссылка на бота для привязки Telegram |
| POST | `/api/v1/auth/telegram-chat-link` | Ссылка-приглашение в чат для привязки Telegram |
| GET | `/api/v1/payments` | Журнал оплат: кто, сколько, когда, откуда (сайт или Telegram). Только админ |
| GET | `/api/v1/health` | Проверка сервиса и БД |
| GET | `/api/v1/hello` | Проверка, что API отвечает |

**Примеры**

```bash
# Вход
curl -X POST http://localhost:5000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "manager@example.com", "password": "manager12345"}'

# Создать платёж
curl -X POST http://localhost:5000/api/v1/recurring-payments \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "Аренда офиса", "amount": "85000", "currency": "RUB",
       "first_due_date": "2026-10-25", "period": "monthly"}'

# Просроченные периоды
curl "http://localhost:5000/api/v1/payment-occurrences?state=overdue" \
  -H "Authorization: Bearer $TOKEN"
```

Варианты тела `PATCH /payment-occurrences/{id}`:

| Тело | Что делает |
|------|-----------|
| `{"status": "paid"}` | Оплачено сегодня |
| `{"status": "paid", "paid_at": "2026-10-20"}` | Оплачено в указанную дату |
| `{"paid_at": "2026-10-19"}` | Исправить дату у оплаченного периода (просрочка пересчитается) |
| `{"status": "unpaid"}` | Отменить отметку, дата очищается |

Фильтры `GET /payment-occurrences`: `state` (`pending`, `overdue`, `paid`,
`paid_late`, `unpaid_all`), `status`, `currency`, `recurring_payment_id`,
`date_from`, `date_to`, `include_inactive`, `include_future`, `order`.

`GET /payments/summary` принимает `date_from`, `date_to` (по сроку оплаты) и
`on_date` — дату, на которую считаются статусы. По каждой валюте возвращаются
суммы и количества: всего, оплачено, не оплачено, просрочено.

**Формат ошибок** единый для всех ответов:

```json
{"code": 403, "status": "Forbidden", "message": "Действие доступно только администратору"}
```

**OpenAPI-спецификация** лежит в репозитории: [`backend/openapi.json`](backend/openapi.json).
Перегенерировать после изменения API:

```bash
docker compose exec backend python -m scripts.export_openapi
```

## Переменные окружения

`backend/` имеет приоритет. В Docker значения приходят из корневого `.env`.

| Переменная | По умолчанию | Назначение |
|------------|--------------|-----------|
| `DATABASE_URL` | `sqlite:///./instance/app.db` | Подключение к БД |
| `JWT_SECRET_KEY` | dev-значение | Секрет подписи токенов — **обязательно замените** |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `720` | Сколько живёт токен |
| `SUPERADMIN_USERNAME` | `superadmin` | Логин суперадмина |
| `SUPERADMIN_PASSWORD` | `superadmin` | Пароль суперадмина |
| `SUPERADMIN_EMAIL` | `superadmin@example.com` | Email суперадмина (для входа) |
| `APP_TIMEZONE` | `Europe/Moscow` | Единый часовой пояс приложения |
| `REMINDER_DAYS_BEFORE` | `3` | За сколько дней до срока напоминать |
| `REMINDER_CHECK_INTERVAL_SECONDS` | `60` | Как часто worker проверяет сроки (минимум 5) |

## Запуск без Docker

Нужны Python 3.12+ и Node.js 22+.

**Backend** (из папки `backend/`):

```bash
cd backend
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt

alembic upgrade head                 # схема БД
python -m scripts.seed_all           # суперадмин из .env + демо-данные
uvicorn main:app --host 0.0.0.0 --port 5000 --reload
```

**Worker** (напоминания и бот), в отдельном терминале из `backend/`:

```bash
python -m app.worker
```

**Frontend**, в отдельном терминале:

```bash
cd frontend
npm install
npm run dev                          # http://localhost:5173
```

Скрипты запускайте через `python -m …` из папки `backend/`. При прямом запуске
файла импорты не сработают.

## Хранение данных, миграции, сброс базы

- **Docker.** База лежит в именованном томе `backend_data`, не в папке проекта. SQLite в режиме WAL не работает на bind-mount в Docker Desktop под Windows. Данные переживают `docker compose down` и перезапуск. Удалить их вместе с томом: `docker compose down -v`.
- **Без Docker.** Файл базы — `backend/instance/app.db`.

Миграции Alembic лежат в `backend/migrations/` и применяются автоматически при
старте контейнера `backend`. Вручную:

```bash
docker compose exec backend alembic upgrade head
# изменили модель:
docker compose exec backend alembic revision --autogenerate -m "что изменили"
```

При старте `scripts.check_schema` сверяет схему базы с моделями. Если схема
разошлась, контейнер не поднимется и напишет в логе, чего не хватает.
Пересоздать базу (данные удалятся, суперадмин и демо-данные создадутся заново):

```bash
docker compose exec backend python -m scripts.reset_db -y
docker compose restart backend worker
```

Схема БД — пять таблиц:

| Таблица | Что хранит |
|---------|-----------|
| `users` | Пользователи: логин, email, хеш пароля (bcrypt), роль, Telegram ID |
| `recurring_payments` | Шаблоны регулярных платежей. Удаление мягкое: `is_active`, `ended_at` |
| `payment_occurrences` | Периоды: срок, статус, фактическая дата, кто и откуда отметил, отметка о напоминании. Название, сумма и валюта копируются из шаблона |
| `revoked_tokens` | Отозванные токены (logout) |
| `telegram_links` | Одноразовые коды привязки Telegram |

Деньги хранятся только в `Numeric(14, 2)` / `Decimal`, без float.

## Частые проблемы

| Проблема | Решение |
|----------|---------|
| Контейнер `backend` не поднимается | `docker compose logs backend`. Если схема разошлась с моделями, выполните `reset_db` (см. выше) |
| Панель пишет «Не удалось связаться с сервером» | Backend не запущен или неверный `VITE_API_URL`. Смотрите вкладку Network в DevTools |
| Напоминания не приходят | Проверьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, что бот добавлен в чат и что сервис `worker` запущен (`docker compose logs worker`). Напоминание приходит один раз на период |
| Кнопка «Оплачено» отвечает «Вы не привязаны» | Привяжите Telegram-аккаунт (см. [Настройка Telegram](#настройка-telegram)) |
| `401` на любой запрос | Токен истёк или отозван через logout — войдите заново |
| `address already in use` | Порт 5000 или 5173 занят. Поменяйте его в `docker-compose.yaml` и `VITE_API_URL` |
| Старые npm-пакеты во фронте | `docker compose up --build --renew-anon-volumes` |
| Registry недоступен (`TLS handshake timeout`) | Поднимитесь из локальных образов: `docker compose up -d --no-build` |
