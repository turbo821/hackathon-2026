# Invoice Keeper — напоминания о регулярных платежах

Система, которая не даёт забыть о регулярных платежах: аренда, подписки, серверы.
Администратор вносит платежи, система за 3 дня до срока напоминает о них в
Telegram-чат (и по почте), пользователи отмечают оплату и следят за просрочками.

Система отвечает на три вопроса: **что и когда оплатить, что уже оплачено и что просрочено.**

| Слой           | Технологии                                                                                |
| -------------- | ----------------------------------------------------------------------------------------- |
| Backend        | Python 3.12, FastAPI, Uvicorn, SQLAlchemy 2.0, Alembic, Pydantic v2, PyJWT, bcrypt, httpx |
| База           | SQLite (режим WAL), файл в Docker-томе                                                    |
| Фоновые задачи | Отдельный процесс `worker`: проверка сроков по расписанию + Telegram-бот (long polling)   |
| Frontend       | JavaScript без фреймворка (ES-модули), Vite, nginx                                        |
| Инфраструктура | Docker, Docker Compose, xray (SOCKS5-прокси для исходящих запросов)                       |

## Быстрый старт

Приложение запускается только через Docker Compose: исходящие запросы в Telegram и
к почте идут через прокси-контейнер `xray`, без него напоминания не дойдут.
Отдельная база не нужна — это SQLite.

```bash
# 1. Настройки: копируем шаблон
cp .env.example .env

# 2. В .env задайте как минимум:
#    JWT_SECRET_KEY  — случайная строка (openssl rand -hex 32)
#    SUPERADMIN_*    — логин, пароль и email администратора
#    TELEGRAM_*      — для напоминаний (см. «Настройка Telegram»)

# 3. Запуск
docker compose up --build
```

> После каждого `git pull` запускайте с `--build`, иначе Docker возьмёт старый образ.

Поднимаются четыре сервиса:

| Сервис     | Что делает                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------- |
| `backend`  | API. При старте применяет миграции, сверяет схему БД, создаёт администратора и демо-данные, затем запускает uvicorn |
| `worker`   | Раз в минуту проверяет сроки и шлёт напоминания; обслуживает Telegram-бота (кнопка «Оплачено», привязка аккаунтов)  |
| `frontend` | Панель: статика, собранная Vite, раздаётся nginx; запросы `/api/` nginx проксирует в `backend`                      |
| `xray`     | SOCKS5-прокси для исходящих запросов в Telegram и к почтовому серверу (см. `PROXY_URL`)                             |

| Что              | Адрес                                          |
| ---------------- | ---------------------------------------------- |
| **Панель**       | http://localhost:5173                          |
| Swagger          | http://localhost:5000/api/v1/docs              |
| OpenAPI (живая)  | http://localhost:5000/api/v1/openapi.json      |
| OpenAPI (файл)   | [`backend/openapi.json`](backend/openapi.json) |
| Проверка живости | http://localhost:5000/api/v1/health            |

Остановка — `docker compose down`, данные при этом сохраняются.

Без настроенного Telegram приложение работает полностью: напоминания просто не
отправляются, а worker пишет об этом в лог.

## Сценарий демонстрации

Полный путь из кейса — от добавления платежа до следующего периода.

**Основной сценарий**

1. **Войти администратором.** Откройте http://localhost:5173, войдите как администратор из `.env` или `manager@example.com` / `manager12345`.
2. **Добавить регулярный платёж.** Вкладка «Регулярные» → «+ Добавить платеж»: название, сумма, валюта, периодичность, дата ближайшей оплаты. Возьмите дату не дальше чем через 3 дня — тогда напоминание уйдёт сразу.
3. **Получить напоминание в Telegram.** Сообщение придёт в чат `TELEGRAM_CHAT_ID` сразу после создания: название, сумма, валюта, дата и кнопка «✅ Оплачено».
4. **Войти пользователем и отметить оплату.** Выйдите, войдите как `user@example.com` / `user12345`, на вкладке «Фактические платежи» нажмите «Оплатить». Можно и кнопкой «Оплачено» в Telegram, если аккаунт привязан ([как привязать](#настройка-telegram)).

**Просрочка и периоды**

5. **Показать просроченный платёж.** Создайте платёж с датой в прошлом, например неделю назад. Он сразу получит статус «Просрочка N дн.», а сумма попадёт в «из них просрочено» на карточке валюты. Фильтр «Просрочено» покажет только такие периоды.
6. **Исправить фактическую дату оплаты.** Отметьте просроченный период оплаченным — статус станет «опоздание N дн.». В колонке «Действие» поменяйте дату в календаре на день срока: опоздание исчезнет, а срок не изменится.
7. **Показать следующий период с отдельным статусом.** Как только текущий период оплачен, в списке появляется следующий (через месяц, квартал или год) со своим статусом «Не оплачено». Прошлый период остаётся в истории.

## Роли и права

По кейсу две роли — администратор и пользователь. Администратор из `.env` в
системе называется **суперадмином** (в панели подписан как _owner_): он может
всё, что требуется от администратора по кейсу.

Дополнительно суперадмин может выдать права администратора другим людям,
чтобы не раздавать всем один пароль из `.env`. Это необязательно: без них
система работает ровно по кейсу.

| Действие                                                | Суперадмин (owner) | Администратор | Пользователь |
| ------------------------------------------------------- | :----------------: | :-----------: | :----------: |
| Смотреть платежи, периоды и итоги                       |         ✅         |      ✅       |      ✅      |
| Отмечать и отменять оплату, исправлять фактическую дату |         ✅         |      ✅       |      ✅      |
| Добавлять и прекращать регулярные платежи               |         ✅         |      ✅       |      ❌      |
| Создавать, менять и удалять обычных пользователей       |         ✅         |      ✅       |      ❌      |
| Журнал оплат (`GET /payments`)                          |         ✅         |      ✅       |      ❌      |
| Назначать и снимать администраторов                     |         ✅         |      ❌       |      ❌      |

- Суперадмин задаётся **только в `.env`** (`SUPERADMIN_USERNAME`, `SUPERADMIN_PASSWORD`, `SUPERADMIN_EMAIL`). Через панель и API его нельзя изменить, удалить или создать второго. При каждом старте сид `scripts.seed_superadmin` приводит аккаунт к значениям из `.env`.
- Логин и email суперадмина зарезервированы — занять их другим пользователем нельзя.
- Ограничения действуют в API, а не только в интерфейсе: скрытые кнопки в панели — лишь удобство.
- После удаления пользователя его токен перестаёт работать. В истории оплат вместо него остаётся пустая ссылка.

## Правила учёта: периоды, статусы, просрочка

**Регулярный платёж** — шаблон: название, сумма, валюта, дата ближайшей оплаты
и периодичность (ежемесячно; дополнительно — ежеквартально и ежегодно).

**Период** — конкретная оплата шаблона со своей датой и отметкой «Оплачено / Не оплачено».

- Периоды создаются от первой даты с шагом периодичности — вплоть до ближайшего неоплаченного периода со сроком сегодня или позже. Если первая дата в прошлом, создаётся вся история.
- Оплатили текущий период — сразу появляется следующий.
- Просрочка не останавливает следующие периоды: наступил новый срок — появился новый период.
- Нет такого числа в месяце — срок переносится на последний день месяца. Даты считаются от исходного числа, без «уползания»: 31.01 → 28.02 → 31.03.
- «Сегодня», просрочка и окно напоминаний считаются в едином часовом поясе `APP_TIMEZONE`, а не в поясе сервера.

**Статусы периода**

| Состояние                           | Когда                                                     |
| ----------------------------------- | --------------------------------------------------------- |
| Ждёт оплаты (`pending`)             | Не оплачено, срок сегодня или позже                       |
| Просрочено (`overdue`)              | Не оплачено, **со следующего дня** после срока            |
| Оплачено (`paid`)                   | Оплачено в день срока или раньше (в день срока — вовремя) |
| Оплачено с опозданием (`paid_late`) | Оплачено после срока                                      |

- При отметке «Оплачено» указывается фактическая дата; без даты ставится сегодня. Будущую дату указать нельзя.
- При отмене отметки дата оплаты очищается.
- Просрочка не хранится в базе, а считается при чтении — поэтому исправление фактической даты сразу убирает ошибочную просрочку, а срок не меняется.

**Прекращение платежа** (`DELETE /recurring-payments/{id}`): платёж становится
неактивным, новые периоды и напоминания больше не создаются. Будущие
неоплаченные периоды удаляются; оплаченные и уже наступившие остаются в
истории с пометкой «платёж прекращён».

## Напоминания

1. Worker раз в `REMINDER_CHECK_INTERVAL_SECONDS` (по умолчанию 60 с) досоздаёт недостающие периоды и проверяет сроки.
2. Выбирает **неоплаченные** периоды **действующих** платежей со сроком в окне _от сегодня до сегодня + `REMINDER_DAYS_BEFORE`_ (по умолчанию 3 дня), по которым ещё не напоминали.
3. Отправляет сообщение: название, сумма, валюта, дата оплаты и сколько осталось дней.

Правила:

- **Без дублей.** Перед отправкой период «захватывается» атомарным `UPDATE … WHERE reminder_sent_at IS NULL` — повторная проверка или параллельный процесс второй раз его не отправят.
- **Платёж добавлен позже чем за 3 дня до срока** — напоминание уходит сразу при создании, не дожидаясь worker.
- **Оплаченный период** напоминания не вызывает.
- **Прекращённый платёж** напоминаний не создаёт.
- **Сбой отправки.** Если ни один канал не доставил сообщение, отметка снимается, и на следующей проверке будет новая попытка.

| Канал        | Куда                                                                                                        | Условие                                          |
| ------------ | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Telegram     | Чат `TELEGRAM_CHAT_ID`, с кнопкой «✅ Оплачено»                                                             | Заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` |
| Email (SMTP) | Всем пользователям с email — одним письмом со скрытыми получателями. Адреса `@example.com` (демо) пропускаются | Заданы `SMTP_ADDR` и `SMTP_PASSWORD`             |

## Настройка почты (SMTP)

Почтовые напоминания — дополнительный канал. Пока `SMTP_PASSWORD` пустой,
письма не отправляются.

```env
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465               # 465 — TLS сразу; 587 — вместе с SMTP_STARTTLS=true
SMTP_STARTTLS=false
SMTP_ADDR=you@mail.ru       # адрес ящика, он же логин; пустым не оставлять
SMTP_PASSWORD=пароль-приложения   # не основной пароль от почты
SMTP_NAME=Invoice Keeper
SMTP_SUBJECT=Напоминание об оплате
SMTP_PROXY=socks5://xray:1080     # пусто — подключение напрямую
```

Проверка настроек, входа и списка получателей:

```bash
docker compose exec backend python -m scripts.check_smtp
docker compose exec backend python -m scripts.check_smtp --to me@example.org   # + тестовое письмо
```

> `check_smtp` проверяет прямое подключение по TLS на 465. Если вы используете
> `SMTP_STARTTLS=true` или `SMTP_PROXY`, проверка подключения может показать FAIL,
> хотя рабочий код письма отправит — ориентируйтесь на логи worker.

## API

Все эндпоинты — под префиксом `/api/v1`. Авторизация — заголовок
`Authorization: Bearer <token>`. В Swagger: выполните `POST /api/v1/auth/login`,
скопируйте `access_token`, нажмите **Authorize** и вставьте его.

**Обязательные эндпоинты кейса**

| Метод  | Эндпоинт                           | Назначение                                                             | Доступ         |
| ------ | ---------------------------------- | ---------------------------------------------------------------------- | -------------- |
| POST   | `/api/v1/auth/login`               | Вход (логин — email, и пароль)                                         | все            |
| GET    | `/api/v1/auth/me`                  | Текущий пользователь                                                   | авторизованные |
| POST   | `/api/v1/auth/logout`              | Завершение сессии (токен отзывается)                                   | авторизованные |
| GET    | `/api/v1/recurring-payments`       | Список регулярных платежей (`include_inactive=true` — с прекращёнными) | авторизованные |
| POST   | `/api/v1/recurring-payments`       | Создание регулярного платежа                                           | админ          |
| DELETE | `/api/v1/recurring-payments/{id}`  | Прекращение платежа и его напоминаний с сохранением истории            | админ          |
| GET    | `/api/v1/payment-occurrences`      | Периоды: оплаченные, просроченные, ожидающие                           | авторизованные |
| GET    | `/api/v1/payment-occurrences/{id}` | Конкретный период                                                      | авторизованные |
| PATCH  | `/api/v1/payment-occurrences/{id}` | Подтверждение или отмена оплаты, исправление фактической даты          | авторизованные |
| GET    | `/api/v1/payments/summary`         | Итоги по валютам                                                       | авторизованные |
| GET    | `/api/v1/users`                    | Список пользователей                                                   | админ          |
| POST   | `/api/v1/users`                    | Создание пользователя                                                  | админ          |
| PATCH  | `/api/v1/users/{id}`               | Изменение пользователя                                                 | админ          |
| DELETE | `/api/v1/users/{id}`               | Удаление пользователя                                                  | админ          |
| GET    | `/api/v1/docs`                     | Swagger-документация                                                   | все            |

**Дополнительные эндпоинты**

| Метод | Эндпоинт                          | Назначение                                                        |
| ----- | --------------------------------- | ----------------------------------------------------------------- |
| PATCH | `/api/v1/auth/me`                 | Привязать или отвязать свой Telegram ID                           |
| POST  | `/api/v1/auth/telegram-link`      | Одноразовая ссылка на бота для привязки Telegram                  |
| POST  | `/api/v1/auth/telegram-chat-link` | Ссылка-приглашение в чат для привязки Telegram                    |
| GET   | `/api/v1/payments`                | Журнал оплат: кто, сколько, когда, откуда (сайт или Telegram); админ |
| GET   | `/api/v1/health`                  | Проверка сервиса и БД                                             |
| GET   | `/api/v1/hello`                   | Проверка, что API отвечает                                        |

**Примеры**

```bash
# Вход
TOKEN=$(curl -s -X POST http://localhost:5000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "manager@example.com", "password": "manager12345"}' | jq -r .access_token)

# Создать платёж
curl -X POST http://localhost:5000/api/v1/recurring-payments \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "Аренда офиса", "amount": "85000", "currency": "RUB",
       "first_due_date": "2026-10-25", "period": "monthly"}'

# Просроченные периоды
curl "http://localhost:5000/api/v1/payment-occurrences?state=overdue" \
  -H "Authorization: Bearer $TOKEN"
```

Варианты тела `PATCH /payment-occurrences/{id}`:

| Тело                                          | Что делает                                                     |
| --------------------------------------------- | -------------------------------------------------------------- |
| `{"status": "paid"}`                          | Оплачено сегодня                                               |
| `{"status": "paid", "paid_at": "2026-10-20"}` | Оплачено в указанную дату                                      |
| `{"paid_at": "2026-10-19"}`                   | Исправить дату у оплаченного периода (просрочка пересчитается) |
| `{"status": "unpaid"}`                        | Отменить отметку, дата очищается                               |

Фильтры `GET /payment-occurrences`: `state` (`pending`, `overdue`, `paid`,
`paid_late`, `unpaid_all`), `status`, `currency`, `recurring_payment_id`,
`date_from`, `date_to` (по сроку), `include_inactive`, `include_future`,
`order` (`asc` — ближайшие сроки первыми, `desc`).

`GET /payments/summary` принимает `date_from`, `date_to` (по сроку оплаты) и
`on_date` — дату, на которую считаются статусы. По каждой валюте — суммы и
количества: всего, оплачено, не оплачено, просрочено.

**Формат ошибок** единый для всех ответов:

```json
{ "code": 403, "status": "Forbidden", "message": "Действие доступно только администратору" }
```

**OpenAPI-спецификация** лежит в репозитории: [`backend/openapi.json`](backend/openapi.json).
Перегенерировать после изменения API:

```bash
docker compose exec backend python -m scripts.export_openapi
```

## Переменные окружения

Шаблон — [`.env.example`](.env.example), без секретов. Рабочий `.env` в git не
попадает. Все сервисы берут значения из корневого `.env`.

| Переменная                        | По умолчанию                  | Назначение                                                            |
| --------------------------------- | ----------------------------- | --------------------------------------------------------------------- |
| `DATABASE_URL`                    | `sqlite:///./instance/app.db` | Подключение к БД                                                      |
| `JWT_SECRET_KEY`                  | dev-значение                  | Секрет подписи токенов — **обязательно замените**                     |
| `ACCESS_TOKEN_EXPIRE_MINUTES`     | `720`                         | Сколько живёт токен                                                   |
| `SUPERADMIN_USERNAME`             | `superadmin`                  | Логин администратора из `.env`                                        |
| `SUPERADMIN_PASSWORD`             | `superadmin`                  | Пароль администратора из `.env`                                       |
| `SUPERADMIN_EMAIL`                | `superadmin@example.com`      | Email администратора (для входа)                                      |
| `APP_TIMEZONE`                    | `Europe/Moscow`               | Единый часовой пояс приложения                                        |
| `REMINDER_DAYS_BEFORE`            | `3`                           | За сколько дней до срока напоминать                                   |
| `REMINDER_CHECK_INTERVAL_SECONDS` | `60`                          | Как часто worker проверяет сроки (минимум 5)                          |
| `TELEGRAM_BOT_TOKEN`              | —                             | Токен бота                                                            |
| `TELEGRAM_CHAT_ID`                | —                             | Чат для напоминаний                                                   |
| `TELEGRAM_BOT_USERNAME`           | —                             | Имя бота для ссылок привязки; если пусто — бот спросит его у Telegram |
| `TELEGRAM_GROUP_CHAT_ID`          | —                             | Чат для привязки через ссылку-приглашение                             |
| `SMTP_HOST`                       | `smtp.mail.ru`                | Почтовый сервер                                                       |
| `SMTP_PORT`                       | `465`                         | Порт                                                                  |
| `SMTP_STARTTLS`                   | `false`                       | `true` — STARTTLS (обычно порт 587)                                   |
| `SMTP_ADDR`                       | —                             | Адрес ящика, он же логин                                              |
| `SMTP_PASSWORD`                   | —                             | Пароль приложения; пусто — почта выключена                            |
| `SMTP_NAME`                       | `Invoice Keeper`              | Имя отправителя                                                       |
| `SMTP_SUBJECT`                    | `Напоминание об оплате`       | Тема письма                                                           |
| `SMTP_PROXY`                      | —                             | SOCKS5-прокси для SMTP                                                |
| `PROXY_URL`                       | —                             | Прокси для исходящих HTTP(S)-запросов `backend` и `worker`            |
| `BOT_PROXY_URL`                   | —                             | Прокси для Telegram Bot API                                           |
| `SEED_DEMO_DATA`                  | `true`                        | Создавать демо-данные                                                 |
| `CORS_ORIGINS`                    | `*`                           | Разрешённые источники (через запятую)                                 |
| `LOG_LEVEL`                       | `INFO`                        | Уровень логирования (`DEBUG` показывает SQL)                          |
| `LOG_FORMAT`                      | `text`                        | `text` или `json`                                                     |
| `LOG_LEVEL_LIBRARIES`             | `WARNING`                     | Уровень для uvicorn, httpx, sqlalchemy                                |
| `VITE_API_URL`                    | `/api/v1`                     | Адрес API для браузера (вшивается в сборку фронта)                    |

**Прокси.** Если сервер свободно ходит в Telegram и к почте, оставьте
`PROXY_URL`, `BOT_PROXY_URL` и `SMTP_PROXY` пустыми. Прокси нужен там, где из
контейнеров нет прямого доступа (например, закрыт IPv4 до Cloudflare): тогда
трафик идёт через сервис `xray`, который берёт только IPv4-адреса.

**`VITE_API_URL`** — адрес для **браузера**. Относительный `/api/v1` значит «тот
же адрес, откуда открыта панель»: nginx внутри контейнера панели перенаправляет
`/api` в бэкенд, и CORS не нужен. Адрес вшивается в образ при сборке — после
изменения пересоберите фронт: `docker compose up -d --build frontend`.

## Хранение данных и миграции

- База лежит в именованном томе `backend_data` и переживает `docker compose down` и перезапуск. Удалить её вместе с томом — `docker compose down -v`. (На bind-mount SQLite в режиме WAL не работает под Docker Desktop на Windows — поэтому том.)

Схема — пять таблиц:

| Таблица               | Что хранит                                                                                                                                 |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `users`               | Пользователи: логин, email, хеш пароля (bcrypt), роль, Telegram ID                                                                         |
| `recurring_payments`  | Шаблоны регулярных платежей. Удаление мягкое: `is_active`, `ended_at`                                                                      |
| `payment_occurrences` | Периоды: срок, статус, фактическая дата, кто и откуда отметил, отметка о напоминании. Название, сумма и валюта — слепок шаблона            |
| `revoked_tokens`      | Отозванные токены (logout)                                                                                                                 |
| `telegram_links`      | Одноразовые коды привязки Telegram                                                                                                         |

Деньги хранятся только в `Numeric(14, 2)` / `Decimal`, без float.

Миграции Alembic лежат в `backend/migrations/` и применяются автоматически при
старте `backend`. Затем `scripts.check_schema` сверяет схему с моделями: если
она разошлась, контейнер не поднимется и напишет в логе, чего не хватает.

```bash
# вручную
docker compose exec backend alembic upgrade head
# изменили модель — новая миграция
docker compose exec backend alembic revision --autogenerate -m "что изменили"

# пересоздать базу с нуля (данные удалятся, администратор и демо-данные создадутся заново)
docker compose exec backend python -m scripts.reset_db -y
docker compose restart backend worker
```

## Логирование и диагностика

Логи пишутся в stdout: `docker compose logs -f backend worker`.

- Каждый HTTP-запрос — одна запись: метод, путь, статус, длительность, пользователь и `request_id`. Тот же `request_id` возвращается в заголовке `X-Request-ID`.
- Важные события (`reminder.sent`, `reminder.all_channels_failed`, `telegram.call_failed`, …) пишутся структурированно — в формате `json` (`LOG_FORMAT=json`) их удобно искать по полям.
- Служебные пути (`/api/v1/health`, `/api/hello`) в журнал не пишутся.

Диагностические скрипты проверяют настройки тем же кодом, что и приложение, и
называют конкретную причину сбоя. Код возврата: 0 — всё в порядке, 1 — есть проблема.

```bash
docker compose exec backend python -m scripts.check_telegram          # токен, чат, прокси
docker compose exec backend python -m scripts.check_telegram --send   # + тестовое сообщение
docker compose exec backend python -m scripts.check_smtp --to me@example.org
```

## Частые проблемы

| Проблема                                       | Решение                                                                                                                                                                         |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Контейнер `backend` не поднимается             | `docker compose logs backend`. Если схема разошлась с моделями — `reset_db` (см. выше). Если `RuntimeError` про `SUPERADMIN_EMAIL` — этот email уже занят другим пользователем |
| Панель пишет «Не удалось связаться с сервером» | Backend не запущен или неверный `VITE_API_URL` (должен быть `/api/v1`). Смотрите вкладку Network в DevTools                                                                     |
| Напоминания не приходят                        | Запущен ли `worker` (`docker compose logs worker`); проверьте `python -m scripts.check_telegram --send`. Напоминание приходит один раз на период                                 |
| Кнопка «Оплачено» отвечает «Вы не привязаны»   | Привяжите Telegram-аккаунт ([Настройка Telegram](#настройка-telegram))                                                                                                          |
| `401` на любой запрос                          | Токен истёк или отозван через logout — войдите заново                                                                                                                           |
| `address already in use`                       | Порт 5000 или 5173 занят — поменяйте его в `docker-compose.yaml`                                                                                                                |
| Не скачиваются npm-пакеты при сборке           | Задайте зеркало: `NPM_REGISTRY=https://registry.npmmirror.com docker compose up --build`                                                                                        |
| Registry недоступен (`TLS handshake timeout`)  | Поднимитесь из уже собранных образов: `docker compose up -d --no-build`                                                                                                         |
